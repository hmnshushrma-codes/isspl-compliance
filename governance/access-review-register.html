1. Purpose

The Access Review Register tracks all periodic user access reviews conducted across Ramdoot Solutions' systems and applications. Regular access reviews are a critical control for ensuring that the principle of least privilege is maintained, orphaned accounts are identified, and access rights remain appropriate as personnel change roles or leave the organisation.

This register supports SOC 2 Trust Services Criteria CC6.1 (logical access security), CC6.2 (access provisioning), and CC6.3 (access removal), as well as the organisation's Access Control Policy (RS-SEC-002).

2. How to Use This Register

Instructions for Reviewers:

  1. Preparation: Before each review cycle, the IT Manager generates a current user access list from each in-scope system or application.
  2. Review Assignment: Each system/application is assigned a reviewer — typically the system owner or designated manager.
  3. Conduct Review: The reviewer examines each user's access against their current role and responsibilities. Flag any accounts that are excessive, dormant, or no longer needed.
  4. Document Findings: Record the number of users reviewed, changes made, and any exceptions found in this register.
  5. Remediation: Any identified exceptions must be remediated within the defined SLA (see Section 4). Record the remediation date.
  6. Sign-Off: The reviewer signs off on the completed review. Evidence (screenshots, export files) is retained in the Evidence Library.
  7. Escalation: Unresolved exceptions past the SLA deadline are escalated to the CISO/Security Officer and reported in the quarterly compliance report.

4. Remediation SLAs

Finding Type Description Remediation SLA
Orphaned Account Active account for a terminated employee or contractor Immediate (within 24 hours of discovery)
Excessive Privilege User has admin or elevated access not required for their current role 5 business days
Role Mismatch Access permissions do not align with user's current department or role 10 business days
Dormant Account Account with no login activity for 90+ days (but user is still active) 15 business days
Documentation Gap Access granted but no corresponding access request or approval on file 15 business days (retroactive documentation or removal)

7. Evidence Requirements

The following evidence must be retained for each access review cycle and stored in the Evidence Library:

  • User access list export: Screenshot or CSV export of all user accounts and their permission levels at the time of review
  • Review worksheet: Documented decisions for each user (retain, modify, remove) with justification
  • Change confirmation: Evidence that identified changes were implemented (e.g., access removal confirmation screenshot)
  • Exception log: Detailed record of any exceptions found, including description and remediation plan
  • Sign-off: Reviewer's acknowledgement that the review was completed accurately

Evidence retention period: minimum [TO BE COMPLETED BY RAMDOOT SOLUTIONS] years, or as required by audit standards and contractual obligations.
