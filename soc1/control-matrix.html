1. How to Read This Matrix

Each row in the control matrix represents a single control activity. The columns are defined as follows:

ColumnDescription
Control ObjectiveThe high-level objective the control supports (mapped to control objectives in RS-SOC1-001).
Control IDUnique identifier in the format RS-SOC1-CTL-xxx.
Business ProcessThe business process or IT function the control operates within.
RiskThe risk the control is designed to mitigate.
Control ActivityDetailed description of the control activity in operational language.
Control OwnerThe individual or role responsible for operating the control. Marked as [TO BE COMPLETED BY RAMDOOT SOLUTIONS] until assigned.
Control FrequencyHow often the control is performed (e.g., Per Event, Daily, Weekly, Monthly, Quarterly, Annually).
Control TypePreventive, Detective, or Corrective.
EvidenceThe artefact(s) that demonstrate the control was performed.
Testing ApproachHow an auditor would test the control (Inquiry, Observation, Inspection, Re-performance).
StatusCurrent implementation status.
ExceptionAny known exception or gap related to the control.

Important: This matrix does not fabricate any financial-processing activities specific to Ramdoot Solutions. All control activities describe general control expectations. Ramdoot Solutions must populate specific system names, process details, and control owners before this matrix is suitable for audit readiness.

3. Control Matrix — Segregation of Duties

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-06: Duties are appropriately segregated to prevent unauthorised or erroneous processing RS-SOC1-CTL-006 Role Assignment A single individual can initiate, authorise, and record a financial transaction without independent oversight Role-based access controls (RBAC) are implemented in in-scope systems such that conflicting duties are separated. A segregation of duties (SoD) matrix is maintained identifying incompatible role combinations. System roles are configured to enforce the SoD matrix. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event (system-enforced) / Annually (SoD matrix review) Preventive SoD matrix document; role configuration in systems; RBAC configuration screenshots Inspection of SoD matrix; review of role configurations in systems; identification of users with conflicting roles Documentation Required --

Identified conflicts are escalated and resolved through access modification or implementation of compensating controls. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Semi-Annually Detective SoD conflict analysis reports; resolution documentation for identified conflicts; compensating control documentation Inspection of SoD review reports; inquiry with reviewer; re-performance of conflict analysis on a sample Documentation Required --

4. Control Matrix — Transaction Processing

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-03: Transactions are processed completely, accurately, and in a timely manner RS-SOC1-CTL-008 Data Input Invalid or incomplete data is accepted for processing, leading to inaccurate financial records In-scope applications implement input validation controls that verify the completeness, format, and range of data submitted for processing. Validation failures are rejected with descriptive error messages, and no partial processing occurs. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Transaction (automated) Preventive Application validation rule documentation; system configuration; error logs showing rejected transactions Inspection of validation rules; re-performance by submitting invalid data and verifying rejection Documentation Required --
CO-03: Transactions are processed completely and accurately RS-SOC1-CTL-009 Data Processing Processing errors result in inaccurate, incomplete, or duplicate records Automated processing controls ensure that each transaction is processed exactly once. Control totals, record counts, or hash totals are generated before and after processing and reconciled. Discrepancies trigger alerts and halt further processing until resolved. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Batch / Per Transaction (automated) Detective Reconciliation reports showing input and output totals; exception/alert logs; resolution documentation Inspection of reconciliation reports for a sample of processing runs; inquiry about exception handling Documentation Required --
CO-03: Transactions are processed completely and accurately RS-SOC1-CTL-010 Data Output Output delivered to user entities contains errors or is incomplete Output generated for user entities is subject to a completeness and accuracy review before delivery. For automated outputs, reconciliation controls verify that all processed transactions are included. For manual outputs, a designated reviewer validates accuracy before release. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Output Cycle Detective Output review logs; reconciliation reports; reviewer sign-off records Inspection of output review documentation for a sample of delivery cycles Documentation Required --
CO-03: Transactions are processed in a timely manner RS-SOC1-CTL-011 Processing Timeliness Delayed processing results in untimely financial data being provided to user entities Service level targets are defined for the timeliness of processing. Monitoring tools track processing completion times against defined targets. Breaches of service level targets are escalated to management and communicated to affected user entities where contractually required. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Daily (monitoring) / Monthly (reporting) Detective Processing time reports; SLA monitoring dashboards; escalation records for breaches Inspection of monitoring reports; inquiry about SLA breach handling Requires Confirmation --

5. Control Matrix — Data Backup and Recovery

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-04: Data is backed up and can be recovered to support continuity of financially relevant services RS-SOC1-CTL-012 Backup Operations Data loss due to system failure, corruption, or disaster renders financial data unrecoverable Automated backups of in-scope system databases and application data are performed daily. Backup success and failure status is monitored, and failures trigger alerts for immediate investigation and remediation. Backups are stored in a geographically separate location or cloud region from the primary data. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Daily (backup) / Per Event (failure alert) Preventive Backup job logs showing success/failure; backup monitoring dashboard; backup storage location confirmation Inspection of backup logs for the reporting period; inquiry about failure handling; verification of offsite storage Documentation Required --
CO-04: Data can be recovered to support service continuity RS-SOC1-CTL-013 Backup Testing Backups are not recoverable when needed due to corruption, configuration errors, or untested procedures Backup restoration tests are performed at least quarterly for in-scope systems. Tests verify that data can be successfully restored to a functional state within defined Recovery Time Objective (RTO) and Recovery Point Objective (RPO) targets. Test results and any identified issues are documented. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Quarterly Detective Backup restoration test reports with results, duration, and comparison to RTO/RPO targets Inspection of quarterly test reports; inquiry about remediation of failed tests Documentation Required --
CO-04: Data can be recovered to support service continuity RS-SOC1-CTL-014 Disaster Recovery Extended service outage due to disaster prevents delivery of financially relevant services A disaster recovery plan (DRP) is maintained for in-scope systems and services. The DRP defines roles, responsibilities, recovery procedures, communication protocols, and alternate processing arrangements. The DRP is tested at least annually through a tabletop exercise or live failover test, and results are documented. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Annually (test) / As Needed (invocation) Corrective Disaster recovery plan document; annual DR test reports with results and lessons learned Inspection of DRP document and test reports; inquiry with DR coordinator Documentation Required --

6. Control Matrix — Change Management for Financial Systems

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-02: System changes affecting financial processing are authorised, tested, and approved RS-SOC1-CTL-015 Change Initiation Unauthorised or undocumented changes are made to in-scope systems All changes to in-scope systems are initiated through a formal change request that includes a description of the change, business justification, risk assessment, and rollback plan. Changes cannot proceed without an approved request. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event Preventive Change request tickets/forms with approval records; change management system logs Inspection of a sample of changes deployed during the period and verification that each has an approved change request Documentation Required --
CO-02: System changes are tested and approved RS-SOC1-CTL-016 Change Testing Untested changes introduce defects that compromise data processing integrity Changes are tested in a non-production environment that is logically separated from the production environment. Test results are documented and reviewed by an individual independent of the developer. Changes with failed tests are not approved for production deployment. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event Preventive Test plans and results; reviewer sign-off; evidence of environment separation Inspection of test documentation for a sample of changes; verification of environment separation Documentation Required --
CO-02: System changes are authorised and approved RS-SOC1-CTL-017 Change Approval & Deployment Changes are deployed to production without proper authorisation, introducing risk to financial processing Production deployment requires approval from an authorised approver who is independent of the developer (segregation of duties). Deployment to production is restricted to authorised personnel. All production deployments are logged with timestamps and the identity of the deployer. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event Preventive Deployment approval records; production deployment logs; access lists for production deployment tools Inspection of deployment records for a sample of changes; verification that approver differs from developer Documentation Required --

7. Control Matrix — Vendor Controls

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-07: Subservice organisations and vendors are monitored and managed RS-SOC1-CTL-018 Vendor Onboarding Engaging a vendor without adequate due diligence introduces unmanaged risk to in-scope services Prior to engagement, vendors that will support in-scope services undergo a risk assessment and due diligence review that evaluates their security controls, financial stability, and compliance posture. The assessment is documented and approved by management. Contractual agreements include security requirements, data handling obligations, audit rights, and incident notification provisions. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event (new vendor) Preventive Vendor risk assessment forms; due diligence reports; signed contracts with security clauses Inspection of vendor onboarding documentation for vendors engaged during the period Documentation Required --
CO-07: Vendors are monitored and managed RS-SOC1-CTL-019 Vendor Monitoring Vendor control environment degrades without detection, introducing risk to customer financial data Critical vendors supporting in-scope services are reviewed at least annually. The review includes obtaining and evaluating the vendor's SOC report (or equivalent assurance), reviewing service performance, and assessing any material changes. Findings are documented and escalated to management. Where a bridge letter is required (gap between SOC report period end and current period), it is obtained and reviewed. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Annually Detective Vendor review reports; SOC report review documentation; bridge letters; management sign-off Inspection of annual vendor review documentation; verification that SOC reports were obtained and reviewed Requires Confirmation --

8. Control Matrix — Incident Management

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-05: Security incidents affecting financial data are identified, reported, and resolved RS-SOC1-CTL-020 Incident Detection Security incidents affecting financial data are not detected in a timely manner Monitoring tools and alerting mechanisms are configured to detect security events relevant to in-scope systems, including unauthorised access attempts, data exfiltration indicators, malware detection, and system integrity violations. Alerts are routed to designated personnel for investigation. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Continuous (automated) Detective Monitoring tool configuration; alert configuration documentation; sample alert logs Inspection of monitoring configuration; review of alert logs for the period; inquiry about alert handling Documentation Required --
CO-05: Incidents are reported and resolved RS-SOC1-CTL-021 Incident Response Incidents affecting customer financial data are not properly managed, leading to prolonged impact A formal incident response procedure exists that defines classification criteria (based on impact to customer financial reporting), escalation paths, response timelines, communication requirements (including notification to affected user entities), and root cause analysis. Incidents are tracked in a centralised system from detection through closure. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event Corrective Incident response procedure document; incident tickets showing classification, timeline, root cause, and resolution; user entity notification records Inspection of incident response procedure; review of incident tickets for the period; inquiry about notification process Documentation Required --
CO-05: Incidents are resolved and prevented from recurrence RS-SOC1-CTL-022 Post-Incident Review Lessons from incidents are not captured, leading to recurrence For incidents classified as high or critical severity, a post-incident review is conducted within 10 business days of closure. The review identifies root cause, contributing factors, and corrective actions. Corrective actions are tracked to completion and validated. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event (post-incident) Corrective Post-incident review reports; corrective action tracking records; validation of corrective action completion Inspection of post-incident reviews for high/critical incidents during the period Requires Confirmation --

9. Control Matrix — Physical Security

Control Objective Control ID Business Process Risk Control Activity Control Owner Frequency Type Evidence Testing Approach Status Exception
CO-08: Physical security of facilities housing in-scope systems is maintained RS-SOC1-CTL-023 Facility Access Unauthorised physical access to facilities leads to theft, damage, or tampering with systems Physical access to office facilities where in-scope systems are accessed or administered is restricted to authorised personnel. Access control mechanisms (badge readers, biometric scanners, or equivalent) are in place at entry points. Visitor access requires registration and escort. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Continuous (system-enforced) Preventive Physical access control system configuration; visitor logs; badge/access card issuance records Observation of physical access controls; inspection of visitor logs for the period Requires Confirmation --
CO-08: Physical security of facilities is maintained RS-SOC1-CTL-024 Physical Access Review Former employees or contractors retain physical access to facilities Physical access rights are reviewed at least quarterly to ensure only currently authorised personnel have access. Access for terminated employees is revoked on the same day as logical access revocation. Access badges are collected upon termination. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Per Event (termination) / Quarterly (review) Detective Quarterly physical access review reports; badge collection records; termination checklists Inspection of quarterly access review documentation; comparison of physical access list to active employee list Documentation Required --
CO-08: Physical security of facilities is maintained RS-SOC1-CTL-025 Environmental Controls Environmental hazards (fire, flood, power failure) damage systems housing financial data Facilities housing in-scope systems (including server rooms or data closets, if applicable) are protected by environmental controls including fire suppression systems, climate control (temperature and humidity monitoring), and uninterruptible power supply (UPS) or backup power. Environmental monitoring alerts are configured and routed to designated personnel. [TO BE COMPLETED BY RAMDOOT SOLUTIONS] Continuous (monitoring) / Annually (inspection) Preventive / Detective Environmental monitoring system configuration and logs; fire suppression inspection certificates; UPS test records Observation of environmental controls; inspection of monitoring logs and maintenance records Requires Confirmation --
